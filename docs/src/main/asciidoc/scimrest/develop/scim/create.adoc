= SCIM create operation customization

SCIM 2.0 create operations use HTTP POST to create new resources.

This document is part of the SCIM 2.0 connector tutorial. See xref:../../index.adoc[] for other topics.

IMPORTANT: The built-in SCIM create handler and the `create { scim { ... } }` customization block are *in development*.
The examples on this page describe the intended behavior; until the wiring lands, object classes that need a create operation can use a REST-style create endpoint (`create { endpoint(POST, ...) { ... } }`, see xref:../rest/create.adoc[create objects]) instead.

== Built-in create

To support create operation you do not need to specify anything for well-behaved SCIM 2.0 servers.

The built-in handler:

* Uses POST to the resource endpoint
* Serializes creatable attributes to JSON
* Handles the response to extract the created object
* Parses the `id` from response as Uid

For the servers which are not well-behaved or have implementation limitations, you may need to customize the create operation (below).

== Limiting create to a supported subset of attributes

Servers often accept only part of the attributes on create. All `creatable` attributes from the schema are supported by default; `supportedAttributes` narrows the set to the supported subset:

[source,groovy]
----
objectClass("User") {
    create {
        scim {
            // only these attributes are accepted/sent on create
            supportedAttributes "externalId", "displayName", "nickName"
        }
    }
}
----

== Attribute-specific configuration and limitations

`supportedAttribute(name)` configures a single attribute — pin a fixed value or attach limitations:

[source,groovy]
----
scim {
    // the server expects a fixed value for userName on create
    supportedAttribute("userName") {
        value "generated"
    }

    // the server accepts at most one value for active per request
    supportedAttribute("active") {
        limitations {
            maxPerRequest 1
        }
    }
}
----

Limitations:

`maxPerRequest N`::
  The maximum number of values of the attribute the server accepts in a single request

== Complete create example (AWS style)

[source,groovy,highlight=3,5,6,7]
----
objectClass("User") {
    create {
        scim {
            supportedAttributes "externalId", "displayName", "nickName",
                "profileUrl", "title", "userType", "preferredLanguage",
                "locale", "timezone", "name", "emails", "addresses", "phoneNumbers"
        }
    }
}
----

== Post-create updates

If an attribute is `updateable` but not `creatable`, the framework issues a follow-up update after create, when updatable attributes are present in create operation:

[source,groovy]
----
objectClass("User") {
    create {
        scim {
            supportedAttributes "userName"
        }
    }

    update {
        scim {
            put {
                supportedAttributes "active"
            }
        }
    }
}
----

The `active` attribute will be set after creation.
