= Develop SCIM 2.0 connector using Polygon SCIMREST framework

This is a reference for developing SCIM 2.0 connectors using the SCIMREST framework.

== Documentation structure

The SCIM 2.0 connector tutorial is organized as progressive steps:

* Schema discovery - Automatic SCIM schema discovery from the server
* Schema customization - Customizing discovered schema with Groovy scripts
* Complex and binary attributes - SCIM path mappings and embedded object classes
* Search operations - Built-in search (UID retrieval, list-all, server-side filtering) and filter declarations
* Create operations - Creating resources via SCIM POST
* Update operations - Updating resources (default SCIM `PATCH` for partial updates; optional full `PUT` for full replacement)
* Delete operations - Deleting resources via SCIM DELETE
* Advanced filters - Filter specifications
* Relationship support - Handling SCIM relationships

== Get started with SCIM 2.0 framework

The SCIMREST Framework provides built-in support for SCIM 2.0 protocol, handling schema discovery, filtering, and standard operations while allowing customization through Groovy DSLs.

=== SCIM 2.0 specific features

The framework includes:

* *Automatic schema discovery* - SCIM schemas are automatically discovered from the server
* *SCIM-specific operations* - Built-in search (UID retrieval, list-all, and server-side filtering) and update (default SCIM `PATCH` for partial updates; optional full `PUT` for full replacement)
* *Attribute mapping* - SCIM path-based attribute resolution
* *Customizable* - Override default behavior with Groovy DSLs when needed



== Initial development steps

=== Read-only connector

. Obtain the documentation for the service/application
. Determine connection & authentication parameters (see the Authentication & authorization topic)
. Implement test connection
. Determine object classes and their attributes
. Schema discovery is automatic - verify the discovered schema in development mode
. Verify search and UID retrieval for each object class (built-in; customize or replace with a custom implementation if the server deviates)
. Determine relationships between object classes
. Verify relationship support (standardized `groups`/`members` relationships are detected automatically)

=== Read-Write Connector

In addition to read-only steps:

. Verify the create operation (built-in for well-behaved servers)
. Verify the update operation (built-in; default SCIM `PATCH`, optional full `PUT`)
. Verify the delete operation (built-in)
